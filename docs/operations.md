# 운용 가이드

[← README](../README.md)

루프 세팅이 끝난 뒤, 루프를 돌리고 멈추고 문제를 풀 때 보는 문서입니다.

## 시작하기 전에

1. **구동 스크립트 시험 실행** — 루프 세팅이 보고에 적어 준 시험 명령(드라이런, Orca 면 스모크 테스트)을 한 번 돌립니다. 구동 스크립트는 프로젝트마다 에이전트가 새로 쓰므로, 첫 구동 전에 도는지 확인하는 것이 가장 싸게 문제를 찾는 방법입니다
2. **환경 파일** — `local-dev` 가 읽는 `.env.local` 에 비밀값을 채웁니다. 병렬이면 코디네이터 워크트리에도 필요합니다(루프 세팅 보고에 위치가 있습니다)
3. **권한 설정** — 루프가 띄우는 세션이 확인 창에서 멈추지 않도록, 파일 쓰기·게이트 명령·`local-dev` 를 에이전트 권한 설정에서 허용합니다. 전체 권한 건너뛰기는 쓰지 않는 것을 권합니다

## 시작·멈춤·재개

- **시작**: `LOOP.md` 8절의 "구동 시작 명령"을 실행합니다. Orca 모드면 **Orca 터미널에서** 실행해야 합니다(Orca CLI 가 실행한 터미널을 코디네이터로 인식합니다). 스크립트는 터미널 밖으로 자신을 분리해 띄우고 그 터미널에 상태판을 그립니다 — 그 뒤 터미널을 닫거나 Ctrl+C 해도 루프는 계속 돕니다(닫히는 것은 상태판뿐입니다). 이미 돌고 있으면 두 번째를 띄우지 않고 알립니다
- **멈춤**: 임시 폴더의 `loop-drive.pid` 에 적힌 프로세스를 끝냅니다(Orca 모드). 이미 떠 있는 워커는 하던 일을 끝내고 결과를 파일로 남깁니다
- **재개**: 같은 구동 명령을 다시 실행합니다. 남아 있는 결과 파일부터 반영하고 이어 갑니다. Orca 모드는 이전에 쓰던 Run 을 이어받으므로 돌던 워커를 잃지 않습니다

## 알림

Orca 모드에서는 스크립트와 작은 감시가 멈춘 상태를 OS 알림(Windows 토스트 등)과 임시 폴더의 `loop-alerts.log` 로 알립니다 — 새 질문, 루프 정지(종료 사유), 스크립트가 죽었거나 한 단계에 너무 오래 묶임, 워커가 사람의 답을 기다림, 깨워도 조용한 워커, 사용량 한도 등. 같은 상태는 한 번만 알립니다.
태스크가 검증까지 통과해 완료될 때와 phase 가 끝날 때도 한 번씩 알립니다 — 잘 돌고 있다는 소식입니다. 완료 소식이 태스크 하나 걸리는 시간보다 오래 없으면 상태판을 보세요(재부팅처럼 스크립트와 감시가 함께 꺼지면 알려 줄 쪽이 없습니다).
질문으로 멈췄다면 `답:` 을 적은 뒤 "다시 시작하라" 알림이 옵니다.

## 질문에 답하기

병렬 루프에서 한 태스크의 질문(`질문: <태스크 ID> — …`)은 그 태스크만 세우고 나머지 슬롯은 계속 돕니다. 병합 충돌·반복 실패처럼 여러 태스크에 걸리는 질문만 루프 전체가 새로 띄우기를 멈춥니다. 루프가 도는 중이면 `답:` 만 적으면 되고, 질문이 여럿이면 `답: <태스크 ID> — …` 처럼 머리를 붙입니다.

루프가 멈추면 `plan_setup/STATE.md` 의 `Next Action` 에 `질문:` 이 있습니다. 병렬이면 **코디네이터 워크트리의** `STATE.md` 가 최신입니다. 그 아래에 `답:` 줄을 적고 구동 명령을 다시 실행합니다.

| 질문의 종류 | 답의 예 |
|---|---|
| 코드 수정 3회 소진 | `답: 이어서` (힌트를 덧붙여도 됨) / `답: 건너뛰라` |
| 미결 사항에 막혀 열 태스크가 없음 | 앞 문서(PRD·TRD 등)에서 미결을 푼 뒤 `답: 해소 OQ-007` |
| phase 완료 묶음 실패 | 테스트·환경을 고쳤으면 `답: 재판정` / 태스크를 다시 하려면 `답: phase-02-task-05 다시` |
| 미활성 게이트 승인 | 허용할 범위와 기한을 적어 답합니다(무기한 승인은 받지 않습니다) |
| 기한이 지난 알림·판단 시점이 온 미결 | 각각 처리 / 다음 phase 까지 연장 / 폐기 중 하나 |

대화형 세션을 열어 말로 답해도 됩니다 — 그 세션이 `답:` 줄을 대신 적습니다.

## 진행 상황 보기

- **상태판**(Orca 모드) — `LOOP.md` 8절의 "상태판 명령"(예: `node harness_setup/scripts/loop-status.mjs`, 한 번만이면 `--once`). 구동 스크립트가 살아 있는지·지금 판단 중인지·슬롯마다 어느 태스크가 어디까지 왔는지·질문 대기 여부를 한 화면에 보여 줍니다. 읽기만 하므로 아무 터미널에서나 띄우고 닫아도 됩니다. Orca 사이드바에는 구동 스크립트와 판단 세션이 나오지 않고, 워커 줄은 `worker-task_<내부 ID>` 로 보여 루프 상태를 알 수 없습니다
- `plan_setup/STATE.md` — 지금 어느 phase·태스크이고 누가 무엇을 하는지(병렬이면 배정표)
- `plan_setup/LOG.md` — 무슨 일이 있었는지. 실패는 `- 실패:` 줄로 남습니다
- 기본 브랜치(`main`) — 검증을 통과해 병합된 결과만 있습니다. 작업 중인 코드는 워크트리에 있습니다

## 문제 해결

| 증상 | 원인과 할 일 |
|---|---|
| `local-dev` 가 전제·환경변수 단계에서 실패 | 런타임·Docker 가 없거나 환경변수가 비었습니다. 사람이 설치·설정할 일입니다 |
| Windows 에서 `pwsh` 를 찾을 수 없음 | PowerShell 7 을 설치하거나, "하네스 업데이트해줘"로 스크립트 호출을 바꿉니다 |
| Orca 명령이 `no_active_sender_terminal` 로 실패 | 구동 스크립트를 Orca 터미널 밖에서 실행했습니다. Orca 터미널 안에서 다시 실행합니다 |
| 시작했더니 "이미 실행 중이거나 비정상 종료" | 앞 스크립트가 아직 돌고 있습니다. PC 재시작이나 강제 종료 뒤라 확실히 멈춘 것이면 구동 명령에 `--force` 를 붙입니다 |
| "정리 필요: <태스크>" 로 멈춤 | 스크립트가 없는 동안 그 워커가 결과 없이 끝났습니다. 확인한 뒤 임시 폴더의 `dispatch-<태스크>.txt` 를 지우고 다시 시작하면 그 태스크가 다시 뜹니다 |
| 워커가 확인 창에서 멈춤 | 에이전트 권한 설정에 필요한 명령이 없습니다. 위 "권한 설정" |
| 같은 테스트가 여러 태스크에서 계속 흔들림 | 루프가 세어서 하네스를 고치거나 질문으로 올립니다. 병렬에서 테스트가 DB 를 공유하고 있다면 격리가 부족한 것이니 "루프 업데이트해줘 — 격리 올리자" |
| `배정 없음:` 으로 멈춤 | 열 수 있는 태스크가 없습니다. 대개 미결 사항에 막힌 것이니 질문에 적힌 미결을 풉니다 |
| 3회 소진이 자주 남 | 재시도를 늘릴 일이 아니라 실패 분류를 볼 일입니다. `LOG.md` 의 분류가 전부 진짜 결함인지 확인합니다 |
| `STATE.md` 와 태스크 문서가 다름 | 태스크 문서가 원본입니다. 다음 세션이 자동으로 맞추고 `LOG.md` 에 남깁니다 |
| 루프가 살아 있는지 모르겠음 | 상태판을 띄웁니다. "○ 멈춤 — <사유>" 면 사유대로, "종료 사유 없음(죽었다)" 면 구동 명령으로 다시 시작합니다. 상태판이 없는 이전 버전이면 "루프 업데이트해줘" |
| 이전 버전이 만든 `LOOP.md` 를 쓰는 중 | "루프 업데이트해줘" — 새 구동 구조로 옮기고 쌓인 알림을 정리합니다 |

## 비용 조절

- **모델 배치**: `LOOP.md` 8절의 역할별 모델 표 한 곳에서 바꿉니다(구현·검증은 보통 급, 판단만 하는 코디네이터는 상위 급이 기본 추천). 바꾸려면 "루프 업데이트해줘"
- **동시 에이전트 수**: 병렬 폭보다 큰 수는 놀기만 합니다. `DAG.md` 의 구간별 폭을 보고 정합니다
- 검증 단계(게이트·분리 검증)를 빼는 것은 비용 조절 수단으로 권하지 않습니다 — 이 플러그인이 지키려는 것이 바로 그것입니다
