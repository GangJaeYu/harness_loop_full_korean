# 용어집

[← README](../README.md)

| 용어 | 뜻 |
|---|---|
| **레이어 (Layer)** | 스킬이 이어지는 단계. 0 아이디어 → 1 PRD·TRD → 2 아키텍처 → 3 플랜 → 4 하네스 → 5 루프 → 6 완료 뒤 |
| **PRD / TRD** | 무엇을 만들지(요구사항) / 어떤 기술로 만들지(기술 결정)를 적은 문서 |
| **FR · NFR · US** | 기능 요구사항 · 비기능 요구사항 · 유저 스토리의 ID 접두어 |
| **TD** | TRD 의 기술 결정 하나 (Technical Decision) |
| **OQ (미결)** | 아직 정하지 않은 질문. 태스크를 막을 수 있고, 사람이 풀면 열립니다 |
| **CF (충돌)** | 앞 문서와 설계가 어긋나는 지점. 숨기지 않고 드러냅니다 |
| **phase** | 끝나면 관찰 가능한 결과가 있는 개발 단계. 태스크 여럿으로 이뤄집니다 |
| **task (태스크)** | 한 세션이 구현하는 작업 단위. frontmatter 에 의존·파일·게이트가 적힙니다 |
| **DAG** | 태스크 의존 그래프. 어떤 태스크를 동시에 돌릴 수 있는지의 근거 |
| **병렬 폭** | 어떤 구간에서 동시에 열 수 있는 태스크 수. 실제 병렬도의 상한 |
| **하네스 (harness)** | 태스크가 끝났다고 말해도 되는 조건을 판정하는 장치. 게이트 정의서와 `local-dev` 스크립트 |
| **게이트 (gate)** | 통과해야 할 검사 하나. `lint` · `unit` · `e2e` · `task_validation` 네 개 |
| **task_validation** | 구현하지 않은 다른 세션이 실행 중인 앱에서 수용 기준을 직접 관찰해 판정하는 게이트 |
| **활성 시점** | 게이트가 실제로 돌 수 있게 되는 태스크. 그전의 결과는 `미활성` 이고 통과로 읽지 않습니다 |
| **흐름 (FLOW-xx)** | e2e 가 검사하는 사용자 흐름 하나 |
| **phase 완료 묶음** | 느려서 매 태스크에서 빼 두고 phase 가 끝날 때 도는 e2e 흐름 |
| **`local-dev`** | 의존 서비스와 앱을 한 명령으로 준비하는 스크립트. 종료 코드로 어느 단계가 실패했는지 알려 줍니다 |
| **토막** | 한 태스크를 세션별로 나눈 조각 — 구현 · 검증 · 반영 |
| **구동 스크립트 (`loop-drive`)** | 세션을 열고 기다리는 스크립트. 판단하지 않습니다 |
| **코디네이터** | 라운드마다 새로 열려 결과를 반영하고 실패를 분류하고 다음 태스크를 배정하는 세션. 문서를 쓰는 유일한 쪽 |
| **워커** | 배정받은 태스크를 구현하거나 검증하는 세션 |
| **슬롯** | 동시에 돌 수 있는 워커 자리 하나. 둘째 슬롯부터 각자 git 워크트리를 씁니다 |
| **코디네이터 워크트리** | 코디네이터와 첫 워커가 쓰는 작업 자리. 기본 브랜치(`main`)는 사용자 자리라 비워 둡니다 |
| **격리** | 슬롯끼리 앱 포트·DB 를 나누는 방식. 슬롯별 환경 통째 / DB 하나에 슬롯별 데이터베이스 / 격리 없이 앱 쓰는 게이트만 순서대로 |
| **진짜 결함 · 낡은 스펙 · 환경 문제 · 흔들림 · 판정 불가** | 실패 분류 다섯. 코드를 고치는 것은 진짜 결함뿐입니다 |
| **재시도 3회** | 진짜 결함에 대한 코드 수정 횟수의 상한. 소진하면 멈추고 묻습니다 |
| **`질문:` / `답:`** | 루프가 사람에게 묻는 줄과 사람이 답하는 줄. `STATE.md` 의 `Next Action` 에 있습니다 |
| **`알림:`** | 루프를 멈추지 않고 다른 담당(사람·다른 스킬)에게 넘기는 메모. 처리 주체와 기한이 붙고, 기한이 지나면 질문으로 올라옵니다 |
| **Standing Decisions** | 사람이 한 번 내린 승인(예: 미활성 게이트 허용). 범위와 기한이 있고 만료되면 루프가 지웁니다 |
| **Orca** | 여러 에이전트를 워크트리별로 띄우고 관리하는 개발 환경(ADE). 병렬 운용에 선택적으로 씁니다 |
