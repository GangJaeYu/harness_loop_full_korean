## 1. 개요

### 1.1 한 줄 정의

국내에서 혼자 일하는 프리랜서 디자이너가 **하나의 프로젝트 아래에 계약서와 인보이스를 묶어** 작성·공유·입금 확인까지 한 화면에서 추적하는 웹서비스.

### 1.2 배경과 문제

프리랜서 디자이너는 동시에 3~6개 프로젝트를 진행하면서, 계약서는 문서 파일로, 인보이스는 표 계산 파일이나 손으로 만든 PDF로, 주고받은 기록은 메일과 메신저로 흩어 놓는다. 셋 사이에 연결이 없다.

그래서 두 달 전 끝난 프로젝트의 잔금이 안 들어왔을 때, 잔금 조건을 확인하려면 계약서를 찾아야 하고 몇 번 청구했는지 확인하려면 인보이스를 따로 찾아야 한다. 결과적으로 **받아야 할 돈을 놓친다.**

현재의 대안과 한계:

| 대안 | 한계 |
|---|---|
| 문서 템플릿 + 표 계산 + 메일/메신저 | 무료이고 익숙하지만 계약↔인보이스↔입금 상태가 사람 머릿속에만 있다 |
| 전자계약 서비스 | 서명은 되지만 돈의 흐름을 모른다. 1인에게는 비싸다 |
| 세무·정산 서비스 | 세금은 처리하지만 계약 문서를 다루지 않는다 |

빈틈은 하나다 — **"이 계약에서 나온 이 청구서가 아직 안 들어왔다"를 한 화면에서 보여주는 것이 없다.**

### 1.3 목표와 비목표

**목표**

1. 계약서와 인보이스가 같은 프로젝트에 묶여 있어, 잔금 조건을 확인하려고 파일을 뒤지지 않게 한다.
2. 발송했는데 입금되지 않은 돈이 로그인 직후 화면에 보이게 한다.
3. 디자이너용 계약서 기본형을 제공해 백지에서 시작하지 않게 한다.
4. 첫 사용자가 계약서 1건 + 인보이스 1건을 만드는 데 15분 이내로 끝나게 한다.

**비목표** (일부러 하지 않는 것)

- 법적 효력을 주장하는 전자서명 — 이번 버전은 문서 작성·공유까지다. (OQ-001)
- 회계·세무의 대체 — 세금계산서 발행, 국세청 신고, 장부 작성은 다루지 않는다.
- 팀 협업 — 멤버 초대, 승인 흐름, 권한 분리를 만들지 않는다.
- 은행 연동에 의한 입금 자동 확인 — 입금 표시는 사용자가 직접 한다.
- 클라이언트(발주사)를 위한 제품이 되는 것 — 발주사는 계정 없이 링크로 문서를 볼 뿐이다.
- 해외 거래 지원 — 다통화, 환율, 영문 문서를 다루지 않는다.

## 2. 사용자

| 유형 | 설명 | 주요 목표 | 기술 숙련도 |
|---|---|---|---|
| **프리랜서 디자이너 (주 사용자)** | 국내에서 개인 자격 또는 개인사업자로 일하는 경력 2~7년 디자이너. 동시 진행 프로젝트 3~6개, 클라이언트는 국내 중소기업·에이전시. 세무사 없이 스스로 정산한다 (가정) | 계약과 청구를 흩어놓지 않고, 받아야 할 돈을 놓치지 않는다 | 웹 도구에 익숙함(디자인 툴·협업 툴 상시 사용). 회계·법률 용어에는 약함 |
| **클라이언트 담당자 (비로그인 열람자)** | 발주사의 실무 담당자. 계정이 없고 만들 생각도 없다. 링크를 받아 문서를 확인하는 것이 전부다 | 받은 계약서·인보이스를 즉시 열어 보고 필요하면 내려받는다 | 다양함. 링크 클릭 이상을 요구하면 이탈한다 |

> 2순위 사용자(1인 개발자·영상 편집자·마케터)는 별도 유형으로 두지 않는다. 목표와 숙련도가 주 사용자와 사실상 같고, 계약서 템플릿 문구만 다르기 때문이다. 이번 버전의 요구사항은 이들을 위해 바뀌지 않는다.

## 4. 기능 요구사항

### 4.1 계정

#### FR-001. 이메일 회원가입과 로그인
- **관련 스토리**: US-001
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 이메일과 비밀번호로 계정을 만들고 로그인한다. 계정은 1인 단위이며 팀 개념이 없다.
- **수용 기준**:
  - [ ] 이메일과 비밀번호를 입력해 가입하면 계정이 생성되고 로그인된 상태로 대시보드가 열린다
  - [ ] 이미 가입된 이메일로 다시 가입을 시도하면 계정이 생성되지 않고 "이미 사용 중인 이메일" 메시지가 표시된다
  - [ ] 비밀번호가 8자 미만이면 가입이 거부되고 사유가 화면에 표시된다
  - [ ] 잘못된 비밀번호로 로그인하면 로그인되지 않고 "이메일 또는 비밀번호가 올바르지 않습니다"가 표시된다(어느 쪽이 틀렸는지는 구분해 알리지 않는다)
  - [ ] 로그인하지 않은 상태에서 대시보드 주소로 직접 접근하면 로그인 화면으로 이동한다

#### FR-002. 비밀번호 재설정
- **관련 스토리**: US-001
- **우선순위**: P1
- **차단 미결**: OQ-011 (메일 도달 확인)
- **설명**: 사용자는 가입한 이메일로 재설정 링크를 받아 비밀번호를 다시 설정한다.
- **수용 기준**:
  - [ ] 가입된 이메일을 입력하면 재설정 링크가 담긴 메일이 발송된다
  - [ ] 가입되지 않은 이메일을 입력해도 화면에는 동일한 안내가 표시되고 메일은 발송되지 않는다
  - [ ] 재설정 링크는 발급 후 24시간이 지나면 동작하지 않고 만료 안내가 표시된다
  - [ ] 재설정을 완료하면 기존 비밀번호로는 로그인되지 않는다

### 4.2 클라이언트와 프로젝트

#### FR-003. 클라이언트 등록·수정·삭제
- **관련 스토리**: US-002, US-013
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 클라이언트를 등록한다. 항목은 상호, 담당자명, 연락처(이메일·전화), 사업자등록번호, 주소, 메모다.
- **수용 기준**:
  - [ ] 상호를 입력하고 저장하면 클라이언트 목록에 나타난다(상호 외 항목은 비워도 저장된다)
  - [ ] 상호가 비어 있으면 저장되지 않고 해당 입력란에 오류가 표시된다
  - [ ] 사업자등록번호를 10자리 숫자가 아닌 값으로 입력하면 저장되지 않고 형식 오류가 표시된다
  - [ ] 프로젝트가 1건 이상 연결된 클라이언트를 삭제하려 하면 삭제되지 않고 연결된 프로젝트 수가 표시된다
  - [ ] 다른 계정이 만든 클라이언트의 상세 주소로 접근하면 내용이 표시되지 않고 404가 반환된다

#### FR-004. 프로젝트 등록과 대금 조건 설정
- **관련 스토리**: US-002
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 클라이언트 아래에 프로젝트를 만든다. 프로젝트는 계약서와 인보이스가 매달리는 중심 개체이며 프로젝트명, 클라이언트, 총 계약금액, 시작일·종료일, 대금 조건(착수금/중도금/잔금의 비율 또는 금액), 상태(진행 예정/진행 중/완료/보류)를 갖는다.
- **수용 기준**:
  - [ ] 프로젝트명·클라이언트·총 계약금액을 입력해 저장하면 클라이언트 상세와 프로젝트 목록 양쪽에 나타난다
  - [ ] 대금 조건을 비율로 입력할 때 합이 100%가 아니면 저장되지 않고 현재 합계가 표시된다
  - [ ] 대금 조건을 금액으로 입력할 때 합이 총 계약금액과 다르면 저장되지 않고 차액이 표시된다
  - [ ] 종료일이 시작일보다 앞서면 저장되지 않고 오류가 표시된다
  - [ ] 총 계약금액에 음수 또는 숫자가 아닌 값을 넣으면 저장되지 않는다
  - [ ] 대금 조건을 비워 두어도 프로젝트는 저장된다(이후 인보이스에서 금액을 직접 입력한다)

#### FR-005. 프로젝트 상세에서 계약서와 인보이스를 한 화면에 표시
- **관련 스토리**: US-010
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 프로젝트 상세 화면 하나에서 그 프로젝트의 계약서 목록과 인보이스 목록, 그리고 청구·수금 요약을 함께 본다. 이 화면이 제품의 존재 이유다.
- **수용 기준**:
  - [ ] 프로젝트 상세 화면에 그 프로젝트의 계약서 목록(문서명·상태·최종 수정일)과 인보이스 목록(번호·금액·상태·발송일)이 스크롤 없이 같은 화면에 표시된다(뷰포트 높이 900px 기준)
  - [ ] 같은 화면에 총 계약금액, 청구 합계, 입금 합계, 미수금 합계가 숫자로 표시된다
  - [ ] 미수금 합계는 발송·연체 상태 인보이스 금액의 합과 일치한다
  - [ ] 계약서나 인보이스가 하나도 없으면 각 목록 자리에 "아직 없습니다"와 생성 버튼이 표시된다
  - [ ] 목록의 계약서 또는 인보이스를 누르면 해당 문서 상세로 이동하고, 되돌아오면 같은 프로젝트 상세로 복귀한다

### 4.3 계약서

#### FR-006. 템플릿 선택과 변수 자동 채움
- **관련 스토리**: US-003
- **우선순위**: P0
- **차단 미결**: **OQ-007** (템플릿의 법적 검토 범위가 정해지기 전에는 템플릿 본문을 확정하지 않는다)
- **설명**: 사용자는 디자이너용 계약서 기본 템플릿(1~2종)을 고르고, 프로젝트·클라이언트·본인 정보가 채워진 초안을 받는다. 템플릿은 수정 횟수, 저작권 귀속, 시안 반려, 추가 요청 비용, 대금 지급 시기 조항을 포함한다.
- **수용 기준**:
  - [ ] 프로젝트 상세에서 '계약서 만들기'를 누르면 사용 가능한 템플릿 목록이 표시된다
  - [ ] 템플릿을 고르면 클라이언트 상호·담당자명·사업자등록번호, 프로젝트명, 총 계약금액, 기간, 대금 조건이 본문에 채워진 초안이 생성된다
  - [ ] 프로젝트에 값이 없는 항목(예: 사업자등록번호 미입력)은 본문에 "[미입력]" 표시로 남고, 그 개수가 화면 상단에 안내된다
  - [ ] 초안 생성 후 프로젝트의 금액을 바꿔도 이미 만든 계약서 본문은 자동으로 바뀌지 않는다
  - [ ] 템플릿을 고르지 않고 빈 계약서로 시작할 수 있다

#### FR-007. 계약서 조항 편집과 저장
- **관련 스토리**: US-003
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 생성된 계약서의 조항 텍스트를 수정하고, 조항을 추가·삭제·순서 변경한 뒤 저장한다.
- **수용 기준**:
  - [ ] 조항 본문을 수정하고 저장하면 다시 열었을 때 수정된 내용이 표시된다
  - [ ] 조항을 추가·삭제·순서 변경할 수 있고, 조항 번호는 저장 시 순서대로 다시 매겨진다
  - [ ] 저장하지 않고 화면을 벗어나려 하면 저장되지 않은 변경이 있다는 확인 창이 표시된다
  - [ ] '발송됨' 상태인 계약서는 본문이 편집되지 않고, 편집하려면 새 버전을 만들어야 한다는 안내가 표시된다
  - [ ] 조항이 하나도 남지 않은 상태로는 저장되지 않는다

#### FR-008. 계약서 PDF 생성
- **관련 스토리**: US-004
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 작성한 계약서를 PDF 파일로 만들고 내려받는다.
- **수용 기준**:
  - [ ] 계약서 상세에서 'PDF 내려받기'를 누르면 PDF 파일이 다운로드된다
  - [ ] PDF에는 화면에 표시된 모든 조항 본문, 당사자 정보, 금액, 기간이 동일하게 포함된다
  - [ ] 본문이 한 쪽을 넘으면 페이지가 나뉘고 각 페이지 하단에 "n / m" 형식의 쪽 번호가 표시된다
  - [ ] 모든 페이지에 FR-011의 고지 문구가 포함된다
  - [ ] 다른 계정의 계약서 PDF 생성 주소로 접근하면 파일이 생성되지 않고 404가 반환된다

#### FR-009. 계약서 공유 링크 발급과 비로그인 열람
- **관련 스토리**: US-004, US-014
- **우선순위**: P0
- **차단 미결**: OQ-009 (클라이언트가 링크에서 무엇까지 할 수 있는지)
- **설명**: 사용자는 계약서마다 공유 링크를 만들어 클라이언트에게 전달한다. 링크를 받은 사람은 로그인 없이 문서를 보고 PDF를 내려받는다.
- **수용 기준**:
  - [ ] '공유 링크 만들기'를 누르면 링크가 생성되어 화면에 표시되고 복사 버튼으로 클립보드에 복사된다
  - [ ] 로그인하지 않은 브라우저에서 그 링크를 열면 계약서 본문이 표시되고 PDF 내려받기 버튼이 동작한다
  - [ ] 공유 화면에는 계약서 본문과 당사자 정보만 표시되고, 소유자의 다른 프로젝트·클라이언트·인보이스 정보는 표시되지 않는다
  - [ ] 링크를 폐기하면 같은 주소로 접근했을 때 문서가 표시되지 않고 "더 이상 유효하지 않은 링크" 안내가 표시된다
  - [ ] 존재하지 않는 링크 주소로 접근하면 404 화면이 표시되고, 문서의 존재 여부를 알 수 있는 정보는 노출되지 않는다

#### FR-010. 공유 링크 열람 기록
- **관련 스토리**: US-005
- **우선순위**: P1
- **차단 미결**: 없음
- **설명**: 공유 링크가 열릴 때마다 시각을 기록하고, 소유자에게 최초·최근 열람 시각과 총 열람 횟수를 보여준다.
- **수용 기준**:
  - [ ] 공유 링크가 열리면 열람 기록이 1건 추가된다
  - [ ] 계약서 상세에 최초 열람 시각, 최근 열람 시각, 총 열람 횟수가 표시된다
  - [ ] 한 번도 열리지 않았다면 "아직 열람되지 않음"이 표시된다
  - [ ] 소유자 본인이 로그인 상태로 문서를 열어본 것은 열람 횟수에 포함되지 않는다

#### FR-011. 법적 효력에 관한 고지
- **관련 스토리**: US-012
- **우선순위**: P0
- **차단 미결**: **OQ-007**
- **설명**: 이번 버전의 계약서는 전자서명을 포함하지 않으므로, 서비스가 법적 효력을 보장하지 않는다는 사실을 사용자와 클라이언트 모두가 보게 한다.
- **수용 기준**:
  - [ ] 계약서 편집 화면 상단에 "본 템플릿은 참고용이며 법적 효력을 보장하지 않습니다"라는 취지의 고지가 항상 표시된다
  - [ ] 생성된 PDF의 모든 페이지에 같은 취지의 고지 문구가 포함된다
  - [ ] 공유 링크로 열람하는 화면에도 같은 고지가 표시된다
  - [ ] 사용자가 이 고지를 숨기거나 삭제할 수 없다

### 4.4 인보이스

#### FR-012. 프로젝트에서 인보이스 생성과 값 승계
- **관련 스토리**: US-006
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 프로젝트 상세에서 인보이스를 만든다. 클라이언트 정보와 대금 조건에서 선택한 회차(착수금/중도금/잔금)의 금액이 자동으로 채워진다.
- **수용 기준**:
  - [ ] 프로젝트 상세에서 '인보이스 만들기'를 누르면 클라이언트 상호·담당자·사업자등록번호·주소가 채워진 초안이 생성된다
  - [ ] 대금 조건에서 회차를 고르면 그 회차의 금액이 항목 금액으로 채워진다
  - [ ] 이미 인보이스가 발행된 회차를 다시 고르면 "이미 청구된 회차입니다"가 표시되고, 사용자가 확인해야 진행된다
  - [ ] 대금 조건이 비어 있는 프로젝트에서는 회차 선택 없이 금액을 직접 입력해 생성할 수 있다
  - [ ] 생성된 인보이스는 해당 프로젝트에 연결되어 프로젝트 상세의 인보이스 목록에 나타난다
  - [ ] 프로젝트를 거치지 않는 인보이스 생성 진입점이 존재하지 않는다

#### FR-013. 인보이스 번호 자동 채번
- **관련 스토리**: US-006
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 인보이스에는 계정 안에서 유일한 번호가 자동으로 부여된다.
- **수용 기준**:
  - [ ] 인보이스를 생성하면 "YYYY-NNNN" 형식의 번호가 자동 부여된다(NNNN은 해당 연도 내 1부터 증가)
  - [ ] 같은 계정 안에서 같은 번호를 가진 인보이스가 두 건 존재하지 않는다
  - [ ] 인보이스를 삭제해도 그 번호는 재사용되지 않는다
  - [ ] 사용자가 번호를 직접 수정할 때 이미 사용 중인 번호를 입력하면 저장되지 않고 사유가 표시된다

#### FR-014. 항목 입력과 부가세·원천징수 계산
- **관련 스토리**: US-007
- **우선순위**: P0
- **차단 미결**: OQ-004 (세금 처리 범위)
- **설명**: 사용자는 인보이스에 항목(내용·수량·단가)을 여러 개 넣고, 공급가액 합계에 대해 부가세 10% 또는 원천징수 3.3%를 적용해 청구 금액을 얻는다.
- **수용 기준**:
  - [ ] 항목을 추가하면 그 항목의 금액이 (수량 × 단가)로 계산되어 표시된다
  - [ ] 공급가액 합계는 모든 항목 금액의 합과 일치한다
  - [ ] 과세 방식으로 '부가세 10%'를 선택하면 부가세 = 공급가액 × 0.1(원 단위 절사), 청구 금액 = 공급가액 + 부가세로 표시된다
  - [ ] 과세 방식으로 '원천징수 3.3%'를 선택하면 원천징수액 = 공급가액 × 0.033(원 단위 절사), 실수령액 = 공급가액 − 원천징수액으로 표시되고 두 값이 모두 문서에 나타난다
  - [ ] 과세 방식으로 '없음'을 선택하면 청구 금액이 공급가액과 같다
  - [ ] 항목이 하나도 없으면 인보이스를 '발송' 상태로 바꿀 수 없고 사유가 표시된다
  - [ ] 수량 또는 단가에 음수를 입력하면 저장되지 않는다

#### FR-015. 인보이스 PDF 생성
- **관련 스토리**: US-006, US-014
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 사용자는 인보이스를 PDF로 만들고 내려받는다.
- **수용 기준**:
  - [ ] 인보이스 상세에서 'PDF 내려받기'를 누르면 PDF 파일이 다운로드된다
  - [ ] PDF에는 인보이스 번호, 발행일, 지급 기한, 공급자·공급받는자 정보, 모든 항목, 공급가액, 세액, 청구 금액, 입금 계좌가 화면과 동일하게 포함된다
  - [ ] 항목이 20개를 넘으면 페이지가 나뉘고 합계 영역은 마지막 페이지에만 표시된다
  - [ ] 다른 계정의 인보이스 PDF 생성 주소로 접근하면 파일이 생성되지 않고 404가 반환된다

#### FR-016. 인보이스 공유 링크
- **관련 스토리**: US-014
- **우선순위**: P0
- **차단 미결**: OQ-009
- **설명**: 인보이스도 계약서와 같은 방식으로 공유 링크를 만들어 클라이언트가 로그인 없이 열람·내려받게 한다.
- **수용 기준**:
  - [ ] '공유 링크 만들기'를 누르면 링크가 생성되어 복사할 수 있다
  - [ ] 로그인하지 않은 브라우저에서 링크를 열면 인보이스 내용이 표시되고 PDF 내려받기가 동작한다
  - [ ] 공유 화면에는 해당 인보이스만 표시되고 소유자의 다른 문서·클라이언트 정보는 표시되지 않는다
  - [ ] 링크를 폐기하면 같은 주소로 접근했을 때 문서가 표시되지 않는다
  - [ ] 초안 상태의 인보이스는 공유 링크가 만들어지지 않고 "발송 상태로 바꾼 뒤 공유할 수 있습니다"가 표시된다

#### FR-017. 인보이스를 메일로 발송
- **관련 스토리**: US-006
- **우선순위**: P1
- **차단 미결**: OQ-011 (메일 도달률은 실험으로 확인)
- **설명**: 사용자는 클라이언트 담당자 이메일로 인보이스 공유 링크가 담긴 메일을 서비스에서 바로 보낸다.
- **수용 기준**:
  - [ ] '메일로 보내기'를 누르면 클라이언트 담당자 이메일이 수신자로 채워진 발송 화면이 열린다
  - [ ] 발송에 성공하면 인보이스 상세에 발송 시각과 수신자 주소가 기록된다
  - [ ] 수신자 이메일이 없거나 형식이 올바르지 않으면 발송되지 않고 사유가 표시된다
  - [ ] 발송에 실패하면 실패 사실과 사유가 화면에 표시되고 인보이스 상태는 바뀌지 않는다

#### FR-018. 인보이스 상태 관리
- **관련 스토리**: US-008
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 인보이스는 초안 → 발송 → 입금완료 상태를 가지며, 입금 확인은 사용자가 직접 표시한다.
- **수용 기준**:
  - [ ] 초안 인보이스를 '발송'으로 바꾸면 발송일이 기록되고 상태가 발송으로 표시된다
  - [ ] 발송 또는 연체 상태에서 '입금 완료'로 표시하면 입금일이 기록되고 미수금 합계에서 그 금액이 빠진다
  - [ ] 입금완료 인보이스를 다시 발송 상태로 되돌리면 입금일이 지워지고 미수금 합계에 다시 포함된다
  - [ ] 초안에서 곧바로 입금완료로 바꿀 수 없고 사유가 표시된다
  - [ ] 상태 변경 시각과 변경 전후 상태가 인보이스 이력에 남는다

#### FR-019. 연체 판정
- **관련 스토리**: US-009
- **우선순위**: P0 (FR-020의 연체 목록이 이 판정 규칙에 의존한다)
- **차단 미결**: 없음
- **설명**: 지급 기한이 지났는데 입금 표시가 되지 않은 인보이스는 연체로 표시된다.
- **수용 기준**:
  - [ ] 발송 상태이고 지급 기한이 오늘보다 이전인 인보이스는 목록과 대시보드에서 연체로 표시된다
  - [ ] 연체 인보이스에는 기한 초과 일수가 함께 표시된다
  - [ ] 입금 완료로 표시하면 연체 표시가 사라진다
  - [ ] 지급 기한이 비어 있는 인보이스는 연체로 판정되지 않는다

### 4.5 대시보드와 검색

#### FR-020. 미수금 대시보드
- **관련 스토리**: US-009
- **우선순위**: P0
- **차단 미결**: 없음
- **설명**: 로그인 직후 첫 화면에서 아직 안 들어온 돈과 그 출처를 본다.
- **수용 기준**:
  - [ ] 로그인하면 대시보드가 첫 화면으로 표시된다
  - [ ] 대시보드에 미수금 합계(발송·연체 인보이스 금액의 합)가 숫자로 표시된다
  - [ ] 연체 인보이스 목록이 기한 초과 일수 내림차순으로 표시되고, 각 줄에 클라이언트명·프로젝트명·인보이스 번호·금액·초과 일수가 있다
  - [ ] 목록의 한 줄을 누르면 그 인보이스가 속한 프로젝트 상세로 이동한다
  - [ ] 진행 중 상태의 프로젝트 목록이 표시되고, 각 줄에 총 계약금액과 그 프로젝트의 미수금이 함께 표시된다
  - [ ] 데이터가 하나도 없는 신규 계정에서는 0원과 함께 "클라이언트 등록부터 시작하세요" 안내가 표시된다

#### FR-021. 앱 내 연체 알림
- **관련 스토리**: US-009
- **우선순위**: P1
- **차단 미결**: 없음
- **설명**: 새로 연체가 발생하면 앱 안에서 알림으로 알린다. 메일 독촉은 보내지 않는다.
- **수용 기준**:
  - [ ] 인보이스가 새로 연체로 판정되면 알림 1건이 생성된다
  - [ ] 읽지 않은 알림 개수가 모든 화면의 상단에 표시된다
  - [ ] 알림을 누르면 해당 인보이스 상세로 이동하고 읽음 처리된다
  - [ ] 같은 인보이스에 대해 중복 알림이 생성되지 않는다

#### FR-022. 문서 검색
- **관련 스토리**: US-011
- **우선순위**: P1
- **차단 미결**: 없음
- **설명**: 사용자는 클라이언트명 또는 프로젝트명으로 계약서와 인보이스를 찾는다.
- **수용 기준**:
  - [ ] 검색어를 입력하면 클라이언트명 또는 프로젝트명에 그 문자열이 포함된 프로젝트·계약서·인보이스가 종류별로 묶여 표시된다
  - [ ] 검색은 대소문자를 구분하지 않고 부분 일치를 지원한다
  - [ ] 결과가 없으면 "검색 결과가 없습니다"와 입력한 검색어가 표시된다
  - [ ] 검색 결과에는 다른 계정의 문서가 포함되지 않는다
  - [ ] 검색어가 비어 있으면 검색이 실행되지 않는다

### 4.6 데이터와 정책

#### FR-023. 문서·클라이언트 삭제
- **관련 스토리**: US-013
- **우선순위**: P1
- **차단 미결**: 없음
- **설명**: 사용자는 자신이 만든 클라이언트·프로젝트·계약서·인보이스를 삭제한다.
- **수용 기준**:
  - [ ] 삭제를 누르면 대상 이름이 포함된 확인 창이 표시되고, 확인해야 삭제된다
  - [ ] 삭제된 문서는 목록·검색·대시보드에서 사라진다
  - [ ] 삭제된 문서의 공유 링크로 접근하면 문서가 표시되지 않는다
  - [ ] 인보이스가 1건 이상 있는 프로젝트를 삭제하면 그 인보이스도 함께 삭제되며, 확인 창에 삭제될 인보이스 건수가 표시된다

#### FR-024. 개인정보 처리방침 안내
- **관련 스토리**: US-012, US-013
- **우선순위**: P0
- **차단 미결**: OQ-010
- **설명**: 서비스는 클라이언트의 성명·연락처·사업자등록번호를 저장하므로, 무엇을 얼마나 보관하는지 사용자가 확인할 수 있어야 한다.
- **수용 기준**:
  - [ ] 가입 화면에서 개인정보 처리방침 문서로 이동하는 링크가 표시되고, 동의하지 않으면 가입이 진행되지 않는다
  - [ ] 로그인 후에도 모든 화면 하단에서 개인정보 처리방침에 접근할 수 있다
  - [ ] 처리방침에 수집 항목, 보관 기간, 파기 시점, 문의처가 명시되어 있다
  - [ ] 계정 삭제 화면에서 삭제 후 데이터가 파기되는 시점이 표시된다
