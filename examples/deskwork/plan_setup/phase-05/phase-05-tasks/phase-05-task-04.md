# phase-05-task-04 — 프로젝트 상세 — 한 화면 배치

## Goal
요약 4개와 계약서·인보이스 두 목록을 900px 뷰포트 안에 배치하고 목록 내부만 스크롤하게 한다.

## Context
이 화면이 제품의 존재 이유다(PRD 4.2절). 계약서 목록은 phase-06 이 차단되어 있는 동안 항상 빈 상태로 표시되며, 그 자리와 생성 버튼은 이 태스크가 만든다.

## PRD 근거
- FR-005: 프로젝트 상세 화면에 그 프로젝트의 계약서 목록과 인보이스 목록이 스크롤 없이 같은 화면에 표시된다(뷰포트 높이 900px 기준)
- FR-005: 계약서나 인보이스가 하나도 없으면 각 목록 자리에 "아직 없습니다"와 생성 버튼이 표시된다
- NFR-001: 프로젝트 상세의 응답 P95 1.5초 이내

## TRD 근거
- TD-002 (확정) — 서버 렌더
- TD-015 (확정)

## Scope
### In Scope
- 요약 4개·두 목록 배치
- 목록 내부 스크롤과 전체 건수
- 빈 상태
- 질의 3개 고정
### Out of Scope
- 계약서 생성 흐름 — phase-06-task-02 (차단)
- 인보이스 생성 진입 — phase-04-task-04

## Acceptance Criteria
1. 계약서 2건·인보이스 3건인 프로젝트를 뷰포트 900px에서 열면 요약 4개와 두 목록이 모두 보이고 페이지 세로 스크롤바가 없다
2. 인보이스 20건인 프로젝트에서도 페이지 세로 스크롤바가 없고 인보이스 목록 영역 안에만 스크롤이 생기며 헤더에 20이 표시된다
3. 계약서가 0건이면 그 자리에 "아직 없습니다"와 생성 버튼이 표시된다
4. 인보이스 한 건을 눌러 상세로 갔다가 뒤로 가기를 하면 같은 프로젝트 상세로 돌아온다
5. 이 화면 1회 렌더에 실행된 질의가 3개이고, 인보이스 50건인 프로젝트에서도 질의 수가 늘지 않는다
6. 초기 표시에 `/api/*` 요청이 0건이다
