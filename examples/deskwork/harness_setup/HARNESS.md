- **입력 문서**: docs/PRD.md (0.1), docs/TRD.md (0.1), docs/ARCHITECTURE/ (0.1), plan_setup/PLAN.md (0.1), plan_setup/phase-01~06 태스크 61건
- **상태**: 사람 검토 대기
- **주의**: 사용자와 대화할 수 없는 조건에서 작성했다. 물었어야 할 것은 `questions.md` 에 그대로 남겼고, 그 자리에서 세운 가정도 함께 적었다.

## 1. 게이트 개요

태스크 하나는 아래 네 게이트를 **순서대로** 통과해야 완료된다. 앞이 실패하면 뒤를 돌리지 않는다.
비용이 싼 순서이기도 하지만 더 중요한 이유가 있다 — 타입이 안 맞는 코드로 돌린 E2E 실패는
그 흐름이 깨졌다는 뜻이 아니라 그냥 컴파일이 안 된다는 뜻이라, 원인을 찾는 데 시간만 쓴다.

| 순서 | 게이트 | 정의서 | 명령 | 활성 시점 | 현재 |
|---|---|---|---|---|---|
| 1 | lint | `quality_gates/lint.md` | `npm run gate:lint` | `phase-01-task-01` | 미활성 |
| 2 | unit | `quality_gates/unit.md` | `npm run gate:unit` | `phase-01-task-01` (통합 테스트는 `phase-01-task-02`) | 미활성 |
| 3 | e2e | `quality_gates/e2e.md` | `npm run gate:e2e` | `phase-02-task-07` | 미활성 |
| 4 | task_validation | `quality_gates/task_validation.md` | (분리 세션 — 서브에이전트) | `phase-01-task-01` | 미활성 |

> `미활성` 은 통과가 아니라 **"아직 판정하지 않음"** 이다.
> 코드가 없는 상태에서 테스트 0건을 실행하면 대부분의 러너가 성공으로 끝나고, 그러면 하네스는
> 처음부터 아무것도 막지 않는 장식이 된다. 그래서 게이트마다 활성 시점을 태스크 ID 로 적었고,
> 활성 전의 실패·0건 실행은 `실패` 가 아니라 `미활성` 으로 기록한다.
> 미활성 상태로 태스크를 완료시킬지는 루프가 아니라 **사람이 정할 일**이다.
>
> `status: blocked` 인 태스크(현재 `phase-06-task-01`~`phase-06-task-12`, 12건)는 **어느 게이트의 대상도 아니다.**
> 차단이 풀리면 `harness-update` 가 활성으로 올린다.

### 게이트 명령이 패키지 스크립트를 부르는 이유

게이트가 도구를 직접 부르고 프로젝트는 자기 스크립트를 부르면, 둘이 다른 설정으로 도는 일이 생긴다.
아래 스크립트가 `package.json` 에 있어야 하며, 이것이 하네스와 프로젝트 사이의 계약이다.

| 스크립트 | 내용 | 누가 만드는가 |
|---|---|---|
| `gate:lint` | `tsc --noEmit && eslint . --max-warnings=0 && prettier --check . && npm audit --audit-level=high` | `phase-01-task-01` |
| `gate:unit` | `vitest run` | `phase-01-task-01` |
| `gate:e2e` | `playwright test --project=chromium --grep-invert @phase-complete` | `phase-02-task-07` |
| `gate:e2e:phase` | `playwright test` (phase 완료 시에만. 게이트 명령이 아니다) | `phase-05-task-05` |
| `report:coverage` | 커버리지 보고 (게이트가 아니다) | `phase-01-task-01` |
| `db:migrate` / `db:rollback` / `db:seed` | 마이그레이션·시드 (`local-dev` 가 부른다) | `phase-01-task-02` / 시드는 하네스가 요구 |

> **도구 설정 파일은 도구가 요구하는 자리(프로젝트 루트)에 둔다** — `tsconfig.json`, `eslint.config.mjs`,
> `.prettierrc`, `vitest.config.ts`, `playwright.config.ts`. `quality_gates/` 로 옮기면 도구가 찾지 못한다.
> 게이트 정의서는 그 파일의 **경로를 가리키는 것**으로 연결한다.

## 2. 로컬 개발 환경

- **명령**: `pwsh harness_setup/scripts/local-dev.ps1`
  — 초기화 `-Reset`, 상태 `-Status`, 로그 `-Logs`, 내리기 `-Down`, 성능용 대량 시드 `-BigSeed`, 앱 제외 `-NoApp`
- **OS**: **Windows** (이 세션이 도는 OS 로 확인했다. TRD 1.3절이 개발자 OS 를 미확인 가정으로 남겨 두었던 항목이다)
  — 주 스크립트는 한 OS 용 하나만 둔다. 두 벌을 만들면 한쪽만 갱신되어 "내 컴퓨터에서는 되는데"를 그대로 재현한다.
  다른 OS 가 실제로 필요해지면 그때 `harness-update` 가 `local-dev.sh` 를 추가한다
- **전제**: Node.js LTS(TD-001), npm, 컨테이너 엔진(Docker Desktop) 실행 중
- **환경변수**: `scripts/.env.example` → 저장소 루트의 `.env.local`. **예시 파일에는 키 이름과 형식만 있고 값이 없다**
- **종료 코드**: 0 성공 / 2 전제 / 3 환경변수 / 4 의존 서비스 / 5 스키마·시드 / 6 앱. 실패하면 실패한 단계 이름과 다음 행동을 출력한다

| 구성 요소 | 형태 | 준비 판정 | 왜 필요한가 |
|---|---|---|---|
| PostgreSQL | 컨테이너 | 컨테이너가 running 이고 **`select 1` 질의가 성공**한다 (포트 확인이 아니다) | TD-003. 운영과 같은 종류의 DB 에서 마이그레이션과 유일 제약을 검증한다. unit 의 통합 테스트가 여기 붙는다(TD-014) |
| 메일 수신함 캡처 | 컨테이너 | 관리 API `GET /api/v1/info` 가 200 을 준다 | TD-009. FR-002·FR-017 을 실제 메일 발송 없이 확인한다. E2E FLOW-08 이 재설정 링크를 여기서 읽는다 |
| 헤드리스 브라우저 런타임 | 로컬 설치 | Chromium·WebKit 런타임이 캐시에 존재한다 | TD-015(e2e)와 TD-017(PDF)이 같은 런타임을 공유한다 |
| 스키마 마이그레이션 + 시드 | 스크립트 | `schema_migrations` 를 조회할 수 있다 | 빈 DB 에서 시작해도 로그인 가능한 계정과 예시 프로젝트가 있어야 화면 개발이 된다. 대량 시드(`-BigSeed`)는 NFR-001·OQ-015 용 |
| 애플리케이션 개발 서버 | 호스트 실행 | `APP_BASE_URL` 이 **응답한다** (포트 열림이 아니다) | TD-002·TD-018. 파일 감시·핫 리로드가 OS 차이에 가장 자주 깨지므로 앱만 호스트에서 돌린다 |
| 예시 환경변수 파일 | 파일 | `scripts/.env.example` 이 존재하고 값이 채워진 줄이 없다 | TD-013·security.md §3.3. 필요한 비밀값 목록이 파일 하나로 보여야 한다 |

> **이 표가 단일 출처다.** 구성 요소가 늘면 여기에 행을 더하고 `local-dev.ps1` 상단의 `$Components` 에
> 항목을 하나, 본문에 같은 모양의 블록을 하나 더한다. 스크립트에 필요한 것의 목록을 흩뿌리지 않는 이유가 이것이다 —
> 표와 대조할 수 있어야 `harness-update` 가 무엇을 고칠지 안다.

### 스크립트가 지키는 것

- **멱등하다** — 이미 준비된 것은 다시 띄우지 않는다(각 블록이 준비 판정을 먼저 한다). 루프가 세션마다 이 명령을 돌린다
- **준비될 때까지 기다린다** — 위 표의 준비 판정이 성공할 때까지. 포트가 열린 것과 쓸 수 있는 것은 다르다
- **전제부터 확인하고 멈춘다** — 없는 것과 설치 방법을 출력하고 절반쯤 진행하지 않는다
- **`-Status` 는 아무것도 띄우지 않고 판정만 출력한다** — 분리된 검증 세션이 실패를 '환경 문제'로 분류하는 수단이다.
  이게 없으면 환경 문제가 구현 실패로 보고되고, 루프가 멀쩡한 코드를 재시도 한도까지 고친다
- **비밀값을 파일에 적지 않는다** — 스크립트와 예시 파일 어디에도 실제 값이 없다

### 여기서 정하지 않는 것

**여러 에이전트가 동시에 도는 경우의 격리는 정하지 않는다.** 워크트리 둘이 같은 DB·같은 포트를 쓰게 되는데,
그것을 격리로 풀지 권한으로 풀지는 루프의 운용 방식이 정해진 뒤에야 답이 나온다.
하네스가 한 일은 **포트·DB 이름·컨테이너 이름을 전부 환경변수에서 읽게 해 둔 것**뿐이고,
실제 격리 방식은 `loop-setup`(Layer 5) 으로 넘긴다.

## 4. 하네스 밖

| 요구사항 | 왜 게이트로 못 덮는가 | 무엇으로 확인하는가 |
|---|---|---|
| NFR-013 — 월간 가동률 99%, 계획 점검 1회 30분 이내 | 가동률은 **배포된 서비스를 외부에서 1분 간격으로 관찰**해야 나오는 값이다. 로컬 환경에서 명령 한 줄로 판정되는 성질이 아니다. 코드 쪽 조건(되돌릴 수 있는 마이그레이션·PDF 동시 생성 2건 제한·폴링 없음)은 각각 `phase-01-task-02`·`phase-04-task-09`·`phase-05-task-06` 이 만들고 그 부분은 게이트가 덮는다 | 외부 가동 확인 서비스 연결과 월간 집계 (TRD 9.4절). **운영 소관이며 하네스가 판정하지 않는다** |
| NFR-015 — 개인정보 국외 이전 금지 (배포 리전) | 배포된 서비스·DB·백업의 **리전 표시**를 확인하는 것이고, 로컬에서 실행되는 코드로는 판정되지 않는다. 로그·응답에 개인정보가 새지 않는 부분(`security.md §3.4`)은 unit 이 덮는다 | 호스팅 콘솔의 리전 확인. TD-016 이 잠정(OQ-010 대기)이므로 지금은 확인할 대상 자체가 없다 |
| NFR-006 — 전 구간 TLS, HTTP→HTTPS 이동 | 로컬 개발 환경은 HTTP 로 돈다. TLS 는 호스팅이 제공하는 인증서에 걸린 배포 속성이다. 비밀번호 평문 미저장 부분은 unit 의 '인증' 커버 영역이 덮는다 | 배포 후 수동 확인 (TRD TD-016 검증 방법) |
| NFR-002 — PDF 생성 10초 이내 (실제 실행 환경 기준) | 로컬에서 잰 시간은 **호스팅 컨테이너에서 잰 시간이 아니다.** TD-017 이 스파이크 필요(OQ-014)로 남아 있는 이유가 그것이다. 로컬 측정은 `phase-01-task-09` 스파이크와 FLOW-04 가 하되, 배포 환경 판정은 여기 밖이다 | `phase-01-task-09` 스파이크 결과 + 배포 후 실측 |

> **조용히 빠뜨리는 것과 명시적으로 밖에 두는 것은 다르다.** 위 네 건은 하네스가 판정하지 않는다는 것이
> 여기 적혀 있으므로, 누군가는 다른 수단으로 확인해야 한다는 사실이 남는다.

## 5. 게이트를 늘리지 않았다

타입 검사·구조 규칙 검사·의존성 취약점 스캔은 **모두 lint 안에** 넣었다.
다섯 번째 게이트를 만들면 모든 태스크의 `verification: [lint, unit, e2e, task_validation]` 과 어긋나고,
그 값을 고치는 것은 Layer 3 의 일이다. 게이트를 늘리는 편이 낫다고 판단되면 만들지 않고 보고한다.

## 6. 하네스가 정한 것 (TRD 가 침묵한 것)

TRD 가 TD 로 고른 도구는 그대로 쓴다. 아래는 TRD 가 정하지 않았고 **되돌리기 비용이 낮아** 하네스가 정한 것이다.

| 항목 | 하네스가 정한 값 | 근거와 되돌리기 비용 |
|---|---|---|
| 린터 | ESLint | TD-001 이 "린터는 이 결정에 따라오는 것"이라며 결정으로 세우지 않았다. 되돌리기: 설정 파일 교체 |
| 포매터 | Prettier (`--check` 만, 쓰기 없음) | 위와 같음. 되돌리기: 설정 파일 교체 |
| 패키지 매니저 | npm | TD-001 이 결정으로 세우지 않았다. 되돌리기: lockfile 재생성 |
| 의존성 취약점 임계 | `high` 이상에서 차단 | **PRD·TRD 에 의존성 심각도 기준이 없다.** 근거 없는 값이므로 사용자 확인이 필요하다 — 보고에 올렸다 |
| 메일 캡처 도구 | Mailpit 컨테이너 | TD-009 는 **운영** 메일 제공자를 정하는 결정이고 잠정이다. 로컬 캡처는 TRD 9.3절이 "메일 수신함 캡처(컨테이너)"라고만 적었다. 되돌리기: 컨테이너 이미지 한 줄 |
| 컨테이너 엔진 | Docker (`docker` 명령) | TRD 는 "컨테이너"라고만 적었다. 되돌리기: 스크립트의 명령 이름 |
| 커버리지 보고 형식 | `text` + `lcov` (게이트 아님) | TRD 침묵. 되돌리기: 옵션 한 줄 |

**되돌리기 비용이 큰 것(러너 교체, 브라우저 도구 추가)은 하나도 정하지 않았다.** 그런 것이 필요해 보이면 TRD 로 돌려보낸다.
