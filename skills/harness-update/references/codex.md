# Codex 환경 보조 지침 (harness-update)

## 무엇이 바뀌었는지 찾기

`harness_setup/` 전체와 `plan_setup/STATE.md`·`LOG.md` 를 읽는다. 하네스 문서는 길지 않아 전문 읽어도 된다.

태스크 상태는 셸로 훑는 편이 정확하다.

```
grep -H '^status:' plan_setup/phase-*/phase-*-tasks/*.md
grep -H '^blocked_by:' plan_setup/phase-*/phase-*-tasks/*.md
```

**차단이 풀린 경우가 가장 잘 빠진다.** 차단은 태스크 문서에서 풀리는데 `대기` 표시는 하네스 문서에 있어서,
둘을 잇는 것이 기억밖에 없다. 풀린 OQ·CF ID로 하네스 전체를 검색해 언급된 곳을 전부 찾는다.

```
grep -rn 'OQ-007\|CF-006' harness_setup/
```

반복 실패도 `LOG.md` 를 검색해 센다. **같은 흐름·검사 ID가 두 태스크에 걸쳐 실패했으면 코드가 아니라 하네스를 의심한다.**

## 고치는 방법

**파일을 통째로 다시 쓰지 않는다.** 하네스 문서에는 활성 시점, 커버 영역의 담당 태스크,
'하네스 결정'·'하네스 밖' 목록처럼 그동안 쌓인 것이 들어 있다. heredoc 으로 전체를 덮어쓰면 그게 사라지고,
사라진 줄은 아무도 눈치채지 못한다. **바뀌는 줄만 고친다.**

스크립트를 고쳤으면 heredoc 의 구분자를 따옴표로 감싸(`<<'EOF'`) 변수가 미리 치환되지 않게 한다.
PowerShell 스크립트는 Windows PowerShell 5.1 이 한글을 읽도록 **UTF-8 BOM** 을 유지한다 —
BOM 이 빠지면 주석이 깨져 파싱 자체가 실패하고, 그 실패는 "환경이 준비 안 됐는데 준비됐다고 말하는" 종류로 나타난다.

고친 스크립트는 **실제로 돌려 본다.** 최소한 상태 확인 경로는 돌아가야 한다.
못 돌렸으면 그 사실을 보고에 적는다.

**STATE.md 와 태스크 문서와 코드는 고치지 않는다.** 읽기만 한다.
승인 모드에 따라 쓰기 권한 요청이 필요하니, 고칠 파일 목록을 작성 직전에 알린다.

## 약화는 표 하나로 모아 한 번에 묻는다

선택지 UI가 없으므로 **③ 약화에 해당하는 것만** 모아 제시한다. 상태 반영(①)까지 물으면
갱신이 대화가 되고, 사람이 하네스를 대신 관리하게 된다.

```
하네스를 낮추게 되는 변경이 2건 있습니다. 승인이 필요합니다.
("1: A, 2: B" 형태로 답해 주셔도 됩니다.)

1) FLOW-05 (공유 링크 폐기) 가 3회 연속 실패합니다
   A) 흔들림 원인을 없앤다 (매번 새 토큰 발급, 준비 판정 보강)  → 권장. 검증 범위 그대로
   B) 폐기 즉시 반영 단언을 뺀다
      → 앞으로 "폐기한 링크가 바로 막히는지"를 아무도 확인하지 않습니다 (NFR-005)

2) 취약점 임계를 high → critical 로
   A) 그대로 둔다        → 지금 걸린 3건을 먼저 처리해야 합니다
   B) critical 로 낮춘다 → high 등급 취약점이 앞으로 게이트를 통과합니다
```

각 선택지에 **그래서 지금부터 무엇이 확인되지 않는지**를 적는다.
"단언 하나를 뺍니다"는 정리로 들리고, "이제 아무도 이걸 확인하지 않습니다"는 결정으로 들린다. 실제로는 후자다.
**약화하지 않는 대안을 항상 먼저 놓는다.**

## 갱신 후

`LOG.md` 끝에 한 줄 덧붙인다 — append-only 파일이라 중간을 고치지 않는다.
약화가 있었으면 무엇을 왜 낮췄고 사용자가 무엇에 동의했는지를 함께 적는다.

루프가 다음에 무엇을 할 수 있는지 명시적으로 남긴다.
예: `갱신 완료: e2e 게이트 활성(FLOW-01·02·03). unit 은 phase-01-task-02 완료 후 DB 통합 묶음이 활성됩니다.`
