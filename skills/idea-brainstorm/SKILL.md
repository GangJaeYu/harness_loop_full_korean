# 아이디어 구체화

## 목적과 입력

사용자 설명·대화의 기존 결정·관련 문서와 현재 프로젝트를 읽고 무엇을 만들지 좁힌다.
사용자가 문제·사용자·범위를 이미 명확히 정했으면 IDEA 작성을 생략하고 아래 단계 전환 기준대로 다음 단계 진행을 확인한다.
기존 코드에서 확인한 사실과 추론한 제품 의도를 구분한다.

## 진행

- README·기존 IDEA/PRD·코드를 먼저 조사한다. 이미 답한 내용과 조사로 확인할 사실은 묻지 않는다.
- 아이디어는 사용자와 대화로 좁힌다. 이 단계의 목적은 내용의 구체성과 사용자 맞춤이며 질문 수를 줄이는 것이 아니다. 문제·첫 사용자·현재 대안·핵심 가치·핵심 흐름·포함/제외·제약·성공 기준·사용 상황과 선호를 필요한 만큼 충분히 묻고, 사용자가 말하지 않았거나 모순된 축을 에이전트 가정으로 채워 확정하지 않는다.
- 한 번에 소수(대개 1~3개)씩 묻고 각 질문에 선택지·묻는 이유·추천안을 붙인다. 답에서 이어지는 다음 질문으로 넘어가며 모호할수록 여러 차례 주고받는다. '모르겠다·추천해줘'에는 추천안과 근거를 제시해 확인만 받는다.
- 방향이 열려 있으면 범위·대상·형태처럼 서로 다른 축에서 갈리는 대안과 추천 근거를 사용자에게 직접 보여 고르게 한다. 확정된 방향에 대안을 억지로 만들지 않는다.
- 사소한 선택과 명시 위임된 선택은 스스로 정한다. 사실·확정 결정·가정·미결을 구분하고 가정에는 근거와 영향을 적는다.
- 사용자가 자기 말로 질문 없이 진행을 지시했거나 질문할 수 없는 세션이면 가정·미결로 기록하고 보고에서 먼저 확인할 항목으로 올린다.
- 실행까지 요청받았다면 환경·권한·외부 의존을 조사하고 목적·예산·금지·실패 처리를 실행 전에 정리한다.
  PRD 전 합의는 IDEA에 보존하고 PRD 작성 시 `## 자율운영 합의`로 연결해 재사용한다.
  전체 시간 상한과 허용 대안·미완료 종료 조건을 남기고 실제 환경 준비·복구 운영은 Harness/Loop 절차로 잇는다.

- 화면 제품의 시각 선호·참고 자료·피할 표현을 보존해 PRD의 미리보기·사용자 확정 단계로 잇는다. 아이디어 합의나 기술 위임은 최종 디자인 승인이 아니다.

## 최소 산출물

필요할 때만 `docs/IDEA.md`에 다음을 짧게 쓴다. 고정 절 수와 빈 표는 필요 없다.

- 문제·첫 사용자·현재 대안 대비 가치
- 가치를 얻는 핵심 흐름과 첫 버전의 포함/제외
- 중요한 제약·관찰 가능한 성공 기준
- 남은 가정·리스크·미결과 확인 방법

기술 선호는 사용자 제약으로 보존한다. 기술 선정은 TRD, 상세 구조는 Architecture,
작업 순서는 Plan에서 정하며 IDEA에 같은 내용을 복제하지 않는다.

## 갱신과 제약

- 기존 문서는 영향 줄만 고치고 사용자 수정·기존 ID·절 참조·결정 이력을 보존한다.
- 없어지는 내용은 대체/제외 이유를 연결한다. 미결의 해소 근거와 변경 이력을 짧게 남긴다.
- 승인된 요청을 다시 승인받지 않는다. 범위·비용·데이터 권한을 미응답으로 확대하지 않는다.
- 이후 문서와 충돌하면 합의 범위 안에서 가장 앞의 영향 문서부터 맞춘다.
- 루트 지침은 후속 실행에 필요한 문서 포인터만 보완한다. 양쪽 파일 전체 동기화는 요구하지 않는다.

## 완료 증거와 연결

작업 시작·중요 결정·종료 때 IDEA나 기존 기록에 현재 단계·확정/미결·다음 행동과 근거를 증분 저장한다.
원 대화 없이 범위·합의를 이어받게 하되 작은 문서 요청에 전체 계획 체계를 만들지 않는다.
사용자 명시 기본값 변경·자식 실행 금지를 우선하고 달라진 보장과 미검증을 기록한다.

문제·사용자·가치·흐름·범위·성공 기준이 서로 맞는지 읽고 확정과 미결의 구분을 확인한다.
작성/생략한 문서와 근거, 남은 결정과 영향을 보고한다. IDEA 작성은 제품 구현 완료의 증거가 아니다.
문서화만 요청받았다면 그 범위로 끝내고 다음 스킬을 제안한다. 다음 단계는 `prd-generator`다.
단계를 마치면 결과(요약·주요 결정·가정·남은 결정)를 보고하고 다음 스킬로 이어 진행할지 사용자에게 확인한다. 수정 요청은 반영해 다시 보고한다. Loop 실행 전까지 모든 단계에 적용하며, 사용자가 자기 말로 단계별 확인 생략을 지시했을 때만 확인 없이 이어 간다. '만들어줘'·'끝까지'나 사전 권한·예산 합의만으로는 생략하지 않고, 에이전트는 확인 생략이나 자동 진행을 먼저 권하거나 추천하거나 생략 방법을 안내하지 않으며, 그렇게 받은 선택도 근거가 아니다. 진행이 확인되면 실행을 사용자에게 떠넘기지 않는다.
