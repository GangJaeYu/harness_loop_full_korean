# Orca 실행 수단

Orca를 실제 사용할 때만 읽는다. 설치된 바이너리가 현재 명령의 기준이다.

- 세션의 CLI 지정값과 개발 환경을 확인해 실행 파일을 고르고 계속 같은 파일을 쓴다.
- `orca skills get orca-cli`와 `orca skills get orchestration`에서 현재 역할에 필요한 안내를 읽는다.
- 실제 상태·권한·작업 폴더·사용 가능한 실행 도구를 확인하고 기존 기능을 재사용한다.
- 위임이 필요하면 목적·소유 파일·금지·수용 기준·남은 예산을 전달한다. 독립·준비된 작업은 본문의 병렬 기본과 배정 조건을 적용하되 불필요한 워커를 만들지 않는다.
- 제출·실행·완료는 각각 실제 상태와 결과로 확인한다. 초안이나 접속 실패를 실행 완료로 읽지 않는다.
- 감독 중에는 현재 Run·Task·Dispatch와 실제 실행 주체를 구분해 이어받는다.
- 결과는 요청과 실제 검증 증거로 판단하고 같은 결과를 중복 반영하지 않는다.
- 조용함·시간 경과·생존 확인 불가만으로 작업을 종료하거나 같은 폴더에 중복 실행하지 않는다.
- Loop 안의 워커 질문은 기존 합의로 해결하거나 허용된 대안/최종 미완료로 처리한다. 사용자 응답 플랫폼을 만들지 않는다.
- 배달·완료 보고·정리 절차는 현재 역할의 공식 안내를 따른다. 프로젝트에 별도 구동·감시 체계를 복제하지 않는다.

- 결과는 현재 Run·Task·Dispatch와 코드/환경을 대조해 늦은 재시도·중복 결과가 현재 배정을 완료시키지 못하게 한다.
- 비상속 검증 실행·상태·완전 결과 회수는 설치 버전의 실제 경로로 시험하며 기존 실행 수단을 복제하지 않는다.
