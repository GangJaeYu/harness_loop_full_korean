# Claude Code 환경 보조 지침 (loop-update)

## 무엇이 바뀌었는지 찾기

Read 로 `loop_setup/LOOP.md` 를 전문 읽는다. 파일 하나이고, 고칠 곳을 정하려면 규칙 전체를 알아야 한다.
`plan_setup/STATE.md` 와 `harness_setup/HARNESS.md` 도 읽는다 — **갱신의 근거는 대개 이 둘의 차이에 있다.**

**만료시킬 승인이 가장 잘 빠진다.** 게이트가 활성됐는데 `Standing Decisions` 에 그 게이트의
미활성 승인이 남아 있으면, 루프가 **실제로 도는 게이트를 "승인받았으니 건너뛴다"로 읽는다.**
활성은 하네스 문서에서 일어나고 승인은 `STATE.md` 에 있어서, 둘을 잇는 것이 사람의 기억밖에 없다.

```
grep -n '미활성\|활성' harness_setup/HARNESS.md
grep -n -A5 'Standing Decisions' plan_setup/STATE.md
```

## 반복되는 중단 찾기

`LOG.md` 를 Grep 해서 **어디서 몇 번 멈췄는지** 센다. 이게 갱신의 유일한 객관적 근거다.

```
grep -n 'failed\|중단\|흔들림\|환경 문제' plan_setup/LOG.md
```

**세는 것만으로는 어느 레이어의 문제인지 안 나온다.** 중단마다 "무엇을 바꾸면 안 걸렸겠는가"를 본다 —
`files` 밖의 파일을 고쳐야 했으면 Layer 3, 같은 흐름이 흔들렸으면 `harness-update`,
승인을 매번 다시 물었으면 여기다. **앞 둘을 여기서 고치면 다른 레이어의 결함을 루프 규칙으로 덮는 것이다.**

## DAG 와 폭을 다시 재기

태스크가 추가·삭제됐거나 차단이 풀렸으면 **다시 잰다.** 눈으로 세지 말고 스크립트로 한다.

```
grep -H '^id:\|^status:\|^depends_on:\|^files:' plan_setup/phase-*/phase-*-tasks/*.md
```

여기서 순환·미존재 참조·`files` 겹침을 확인하고, 층별로 나눠 **구간별 폭**을 낸다.
`loop-setup` 이 처음 잰 숫자는 그때의 태스크 목록 기준이라, 태스크가 바뀌면 그대로 두면 안 된다.
**폭이 틀리면 "넷으로 돌리자"는 결정이 근거 없이 유지된다.**

Explore 서브에이전트에게 frontmatter 를 표로 뽑게 해도 된다. 다만 **무엇을 고칠지의 판단은 직접 한다.**

## 고치는 방법

**Write 가 아니라 Edit 을 쓴다.** `LOOP.md` 에는 이 프로젝트의 실제 값, 원본 예시에서 조정한 항목과 그 이유,
닫힌 미결의 흔적, 실측한 DAG 결과가 쌓여 있다. 통째로 다시 쓰면 **그게 조용히 사라지고 아무도 눈치채지 못한다.**

`STATE.md` 의 절 형식을 넓힐 때(병렬에서 `Retry` 를 태스크별 블록으로 등)는
**기존 값을 새 형식으로 옮긴 뒤** 형식을 바꾼다. 넓히면서 지우면 진행 중인 재시도 이력이 없어지고,
그 태스크는 앞의 시도를 처음부터 반복한다.

**`STATE.md` 의 값은 건드리지 않는다.** `Current Task`·`Task Status`·`Last Verification` 은
루프를 도는 세션의 것이다. 여기서 만지는 것은 **절의 형식과 만료된 승인** 둘뿐이다.

## 사용자에게 묻는 지점

AskUserQuestion 을 쓰는 자리는 둘이다.

**격리 미결을 닫을 때.** 선택지 셋(환경 통째 분리 / DB 하나에 워크트리별 계정·권한 / 공유 자원 게이트만 직렬화)에
**되돌리기 비용**을 적어 제시한다. 그리고 **다시 잰 폭을 함께 보여준다** —
넷이 실제로 차는 구간이 없으면 격리 비용만 치르게 되고, 그 사실을 알고 고르는 것과 모르고 고르는 것은 다르다.

**③ 완화를 적용하기 전에.** 무엇이 더 이상 루프를 멈추지 않는지를 `option.description` 에 적는다.
"기록을 줄인다"가 아니라 **"세션이 중간에 끊기면 그 태스크를 처음부터 다시 한다"** 로 적어야
사용자가 실제로 무엇에 동의하는지 안다.

**재시도 3회·분리 세션·게이트 구성은 묻지 않는다.** 원본 사양과 Layer 4가 정했고 이 스킬이 못 바꾼다.
늘려 달라는 요청을 받으면 **묻는 대신 `LOG.md` 를 확인해** 그 3회가 실제로 무엇에 소모됐는지를 답으로 준다.

## 다음 단계

갱신이 끝나면 **루프를 이어서 돌린다.** 이 스킬이 아니라 `LOOP.md` 와 `STATE.md` 가 안내한다.
다만 `Standing Decisions` 를 지웠다면 **다음 태스크에서 그 게이트에 대해 다시 묻게 된다** —
그게 정상이고, 그러라고 만료시킨 것이다.
