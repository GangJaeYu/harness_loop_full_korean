# Claude Code 환경 보조 지침 (prd-generator)

## 미결 사항 결정은 AskUserQuestion 으로

1단계에서 `docs/IDEA.md` 의 미결 사항을 처리할 때, "지금 결정한다"에 해당하는 항목은 `AskUserQuestion` 으로 묻는다.
평문으로 나열하면 사용자가 일부만 답하고 넘어가는데, 미결이 하나라도 남으면 그 위에 세운 요구사항이 통째로 흔들린다.

- 한 번의 호출에 최대 4개까지 묶되, **앞의 답에 따라 뒤 질문의 선택지가 달라지는 것은 묶지 않는다.**
- `option.description` 에는 그 선택이 **어느 요구사항을 만들거나 없애는지** 적는다.
  ("B를 고르면 FR로 결제 연동이 들어오고 P0가 3개 늘어납니다.")
- **'질문' 종류의 미결만 여기에 넣는다.** '확인'(외부 사실 확인 필요), '실험'(해봐야 앎), '유예'(지금 정하면 틀림)에 해당하는 미결을
  객관식으로 물으면 사용자는 모르는 것을 찍게 되고, 그 답이 확정된 합의로 문서에 박힌다. 이 셋은 묻지 말고 미결 표에 경로를 적는다.
- 범위를 줄이는 선택지를 항상 하나 포함한다. 사용자는 대개 범위를 키우는 쪽으로 기울고, PRD 단계에서 커진 범위는 뒤에서 되돌리기 어렵다.

## 기존 코드베이스 확인

기존 프로젝트에 얹는 PRD라면 Glob·Grep으로 실제 기능을 확인한 뒤 쓴다. 라우트 정의, 페이지 파일 목록, README의 기능 목록이
가장 빠른 단서다. 서브에이전트를 쓸 수 있으면 Explore 에이전트에게 "현재 구현된 사용자 기능 목록"을 조사시키고,
그 결과를 PRD의 '이미 있는 것'으로 삼는다. 이 확인 없이 쓴 PRD는 이미 있는 기능을 다시 만드는 태스크를 낳는다.

## 파일 작성과 검토 요청

`docs/PRD.md` 는 Write 도구로 만든다. 이미 있으면 덮어쓰기 전에 읽고, 버전을 올릴지 새로 쓸지 확인한다.

작성 후 미결 사항이 남아 있으면, 사용자가 한 번에 결정할 수 있도록 마지막에 `AskUserQuestion` 으로 한 번 더 묶어 제시하는 것이 좋다.
이 결정들이 TRD의 입력이 되므로 여기서 미루면 다음 스킬이 다시 멈춘다.

## 다음 스킬 연결

사용자가 검토를 마치고 동의하면 Skill 도구로 `trd-generator` 를 호출한다. 동의 전에는 호출하지 않는다.
