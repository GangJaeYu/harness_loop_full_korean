# Codex 환경 보조 지침 (prd-generator)

## 미결 사항 결정은 번호 목록으로 한 번에

선택지 UI가 없으므로, 1단계의 미결 사항은 **표 하나로 모아서** 제시하고 한 번에 답을 받는다.
질문을 대화 여러 턴에 흩뿌리면 답이 누락되고, 누락된 미결 위에 요구사항을 쓰게 된다.

```
아래 4가지만 정해 주시면 PRD를 쓸 수 있습니다. ("1-B, 2-A, 3-B, 4-기타: ..." 형태로 답해 주셔도 됩니다.)

1. 결제를 서비스 안에서 받나요?
   A) 계좌 안내 + 수동 확인  → 요구사항 2개, 가장 가벼움
   B) PG 연동 결제           → 요구사항 6개 추가, 심사 기간 별도 필요
...
```

각 선택지에는 반드시 **그 선택이 요구사항을 몇 개 만들거나 없애는지**를 붙인다. 범위 감각 없이 고르면 P0가 부풀어 오른다.

목록에는 '질문' 종류의 미결만 올린다. '확인'·'실험'·'유예'에 해당하는 미결을 객관식으로 물으면
사용자는 모르는 것을 찍게 되고 그 답이 확정된 합의가 된다. 이 셋은 미결 표에 해소 경로를 적고 넘어간다.

## 기존 코드베이스 확인

기존 프로젝트라면 셸에서 라우트·페이지 파일 목록과 README를 먼저 확인하고 '이미 있는 것'을 구분한다.
추측으로 현재 상태를 적지 않는다.

## 파일 작성

`docs/PRD.md` 는 파일 쓰기 도구나 heredoc으로 만든다. 표가 많으므로 마크다운 표 정렬이 깨지지 않는지 작성 후 확인한다.
승인 모드에 따라 쓰기 권한 요청이 필요할 수 있으니, 작성 직전에 경로를 알린다.
