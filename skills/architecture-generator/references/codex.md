# Codex 환경 보조 지침 (architecture-generator)

## 두 문서를 읽는 방법

`docs/PRD.md` 와 `docs/TRD.md` 를 **전문**으로 읽는다. PRD의 4·5·8·9절과 TRD의 2절·각 TD 확정도·10절·12절은 요약본으로 대체하지 않는다.
충돌은 세부 문장에서 나오기 때문이다. "PDF 10초"(NFR)와 "서버에서 브라우저로 렌더"(TD)가 부딪히는 것은 요약본에는 남지 않는다.

기존 프로젝트라면 셸에서 디렉터리 구성, 라우팅 파일, 스키마·마이그레이션, 설정 파일을 먼저 확인한다.
현재 구조를 추측으로 적으면 Layer 3이 존재하지 않는 파일을 태스크의 Files 에 넣는다.

## 충돌 해소는 번호 목록으로 한 번에

선택지 UI가 없으므로, 발견한 충돌을 **표 하나로 모아** 제시하고 한 번에 답을 받는다.
충돌을 여러 턴에 흩뿌리면 답이 누락되고, 누락된 충돌은 봉합된 것과 구별되지 않는다.

```
설계 중에 앞 문서와 어긋나는 지점 3건을 찾았습니다. 어느 쪽으로 갈지 정해 주세요.
("CF-001: B, CF-002: A, CF-003: 잘 모르겠음" 형태로 답해 주셔도 됩니다.)

CF-001  NFR-002(PDF 10초)  ↔  TD-017(서버에서 브라우저 렌더)
  A) TD-017을 문서 생성 라이브러리로 교체  → TRD 3절(스택)과 PDF 레이아웃 설계를 다시 씁니다
  B) NFR-002를 20초로 조정               → PRD 5절과 FR-008 수용 기준을 고칩니다. 설계는 그대로
  C) 비동기 생성으로 전환                 → FR-008의 흐름이 바뀌어 PRD·설계 양쪽을 고칩니다
  (현재 잠정 설계: C. backend.md §3.4에 표시해 두었습니다)
```

각 선택지에는 반드시 **어느 문서를 고치게 되는지와 무엇이 다시 그려지는지**를 붙인다.
영향 감각 없이 고르면 사용자는 가장 싸 보이는 것을 고르고, 실제 비용은 Layer 3에서 청구된다.

목록에는 사용자가 **판단할 수 있는 것**만 올린다. 미결 중 `확인`·`실험`·`유예` 는 객관식으로 묻지 않는다 —
모르는 것을 찍게 되고 그 답이 확정된 합의가 된다. 이 셋은 미결 표에 해소 경로를 적고 넘어간다.

## 파일 작성

`docs/ARCHITECTURE/` 디렉터리를 만들고 각 파일을 파일 쓰기 도구나 heredoc 으로 만든다.
표와 mermaid 블록이 많으므로 작성 후 마크다운 표 정렬과 코드 펜스가 깨지지 않았는지 확인한다.
mermaid 는 렌더 여부를 확인할 수 없으니 `flowchart LR` 과 `sequenceDiagram` 정도로 단순하게 유지한다.

overview.md 를 마지막에 쓴다. 문서 지도·추적표·CF 표가 영역 문서를 다 쓴 뒤에야 정확해진다.
승인 모드에 따라 쓰기 권한 요청이 필요할 수 있으니, 작성 직전에 만들 파일 목록과 경로를 알린다.

이미 `docs/ARCHITECTURE/` 가 있으면 통째로 덮어쓰지 않는다. 사용자가 손으로 고친 설계가 사라진다.

## `AGENTS.md` 는 `CLAUDE.md` 를 가리키는 한 줄

Codex 는 프로젝트 루트의 `AGENTS.md` 를 자동으로 읽고 `CLAUDE.md` 는 읽지 않는다. 본문을 두 파일에 두면 곧 어긋나므로
본문은 SKILL.md 의 "`CLAUDE.md` 갱신" 절대로 `CLAUDE.md` 에만 쓰고, `AGENTS.md` 에는 아래 한 줄만 둔다.
없으면 만들고, 이미 다른 내용이 있으면 그 줄을 맨 위에 더한다.

```
CLAUDE.md 를 읽고 따른다.
```
