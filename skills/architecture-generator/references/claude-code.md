# Claude Code 환경 보조 지침 (architecture-generator)

## 두 문서를 읽는 방법

`docs/PRD.md` 와 `docs/TRD.md` 는 Read 로 **전문**을 읽는다. 특히 아래는 요약하지 말고 그대로 본다.

| 문서 | 절 | 왜 |
|---|---|---|
| PRD | 4절(FR), 5절(NFR), 8절(가정·미결), 9절(추적표) | 설계가 만족시켜야 할 목록 전체이자 추적표의 왼쪽 열 |
| TRD | 2절(결정 요약), 각 TD의 확정도, 10절(NFR 실현표), 12절(미결) | 어느 결정 위에 세우는지, 어디가 잠정인지 |

**충돌은 세부 문장에서 나온다.** 요약본으로 읽으면 "PDF 10초"와 "서버에서 브라우저 렌더" 가 부딪히는 것을 못 본다.
파일이 길어 한 번에 안 들어오면 offset·limit 으로 나눠 읽되, 건너뛰지 않는다.

Explore 서브에이전트에게 "PRD의 NFR과 TRD의 TD 중 서로 어긋나 보이는 쌍을 찾아라"를 시켜 **2차 검토**로 쓸 수 있다.
다만 그 결과를 그대로 CF 표에 옮기지 않는다 — 판단 기준("어느 한쪽 문서를 고쳐야만 풀리는가")은 직접 적용한다.

## 기존 코드베이스가 있으면

Glob·Grep 으로 현재 구조를 먼저 확인한다. 디렉터리 구성, 라우팅 파일, 스키마·마이그레이션, 설정 파일이 가장 빠른 단서다.
기존 프로젝트의 아키텍처 문서는 "무엇을 만들까"가 아니라 **"지금 무엇이고, 무엇을 바꿀 것인가"**다.
현재 구조를 추측으로 적으면 Layer 3이 존재하지 않는 파일을 태스크의 Files 에 넣는다.

## 충돌과 미결은 AskUserQuestion 으로

충돌 해소(8단계)는 `AskUserQuestion` 으로 묻는다. 충돌마다 **선택지 셋 이하**를 옵션으로 올리고,
`option.description` 에는 그 선택이 **어느 문서를 고치게 되는지와 무엇이 다시 그려지는지**를 적는다.
("NFR-002를 20초로 조정하면 PRD 5절과 FR-008의 수용 기준을 고칩니다. 설계는 그대로 갑니다.")

한 번의 호출에 최대 4개까지 묶되, **앞의 답이 뒤 선택지를 바꾸는 것은 묶지 않는다.**
인증 모델에 걸린 충돌의 답이 권한 검사 지점 설계를 바꾸므로, 이 둘은 같은 호출에 넣지 않는다.

미결 중 `확인`·`실험`·`유예` 는 객관식으로 묻지 않는다. 사용자가 모르는 것을 찍게 되고, 그 답이 확정된 합의로 문서에 박힌다.
이 셋은 미결 표에 해소 경로를 적고 넘어간다. **`질문` 종류만 선택지와 함께 올린다.**

## 파일 작성

`docs/ARCHITECTURE/` 디렉터리를 만들고 각 파일을 Write 로 쓴다. overview.md 를 마지막에 쓰는 편이 낫다 —
문서 지도·추적표·CF 표가 영역 문서를 다 쓴 뒤에야 정확해지기 때문이다.

이미 파일이 있으면 덮어쓰기 전에 Read 로 읽고, 버전을 올릴지 새로 쓸지 확인한다.
특히 `docs/ARCHITECTURE/` 가 이미 있는데 PRD·TRD가 바뀐 경우, 통째로 다시 쓰면 사용자가 손으로 고친 설계가 사라진다.

mermaid 다이어그램은 렌더 여부를 확인할 수 없으므로 문법을 단순하게 유지한다. `flowchart LR` 과 `sequenceDiagram` 정도면 충분하다.
