# Codex 환경 보조 지침 (code-to-docs)

## 코드 훑기

1단계의 여섯 자리는 셸로 잡는다 — `grep -rn` 으로 라우트 등록·환경변수·테스트 파일을, `find` 로 페이지·스키마·설정 파일 목록을.
관찰 목록의 근거 열에 파일과 줄 번호를 그대로 옮긴다. 추측으로 현재 상태를 적지 않는다.

앱을 띄워 관찰할 때는 `package.json` 의 `start` 같은 기존 스크립트를 쓰고, 저장 데이터를 바꾸는 요청은 보내지 않는다.

## 질문은 번호 목록으로, 단 하나만

6단계 중간 보고에서 선택지를 주는 것은 **테스트 도구(질문 OQ) 하나**다.

```
테스트 도구를 정해 주세요. 답이 없으면 A 로 진행합니다.
  A) <표준 러너> — 설정 파일 0개, 기본값
  B) <다른 러너> — 설정 파일 1개, 기존 팀이 쓰던 것이면 이쪽
```

`확인` 종류의 OQ 는 선택지 없이 목록으로만 보여 주고 "답을 못 주셔도 지금 동작대로 테스트를 씁니다"를 붙인다.

## 파일 작성

세 문서는 파일 쓰기 도구나 heredoc 으로 만든다. `docs/PRD.md` 가 이미 있으면 쓰지 않는다(1단계). 표가 많으므로 작성 후 마크다운 표 정렬을 확인한다.
승인 모드에 따라 쓰기 권한 요청이 필요할 수 있으니 작성 직전에 경로를 알린다. `AGENTS.md` 가 이미 있으면 읽고 기존 내용 아래에 더한다.

## 다음 스킬 연결

Codex 에서는 스킬 자동 호출을 기대하지 말고 **다음 단계를 명시적으로** 남긴다. 세 스킬을 순서대로, 각각의 호출 지시(SKILL.md 7~9단계)와 함께.

```
다음 단계 1: plan-generator 스킬(SKILL.md)을 읽고 아래 지시대로 plan_setup/ 을 만듭니다.
  <7단계 호출 지시 전문>
다음 단계 2: harness-setup 스킬 — <8단계 호출 지시>
다음 단계 3: loop-setup 스킬 — <9단계 호출 지시>
끝나면 code-to-docs 10단계(상태 확인·현재 단계 줄·루프 안내)로 돌아옵니다.
```

같은 세션에서 이어서 하면 각 스킬의 `SKILL.md` 를 읽고 그 절차를 따르되, 위 지시를 자기에게 적용한다.
