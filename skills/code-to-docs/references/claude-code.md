# Claude Code 환경 보조 지침 (code-to-docs)

## 코드 훑기

1단계의 여섯 자리는 Glob·Grep 으로 빠르게 잡힌다 — 라우트 정의(`router.(get|post|patch|delete)`, 데코레이터, 핸들러 등록), 페이지·컴포넌트 파일 목록,
스키마·마이그레이션, 환경변수 읽는 곳(`process.env`, `os.environ`), 테스트 디렉터리와 설정 파일.
**관찰 목록의 근거 열에는 파일과 줄을 적어야 하므로** Grep 결과의 줄 번호를 그대로 옮긴다.

코드가 크면 Explore 서브에이전트에게 **"모든 라우트·화면·CLI 명령을 파일:줄과 함께 표로"** 를 시켜도 된다.
다만 수용 기준을 쓰는 것(무엇이 관찰이고 무엇이 판단인가)은 직접 한다 — 서브에이전트는 "버그"라고 적어 올리기 쉽다.

앱을 띄워 관찰할 때는 `harness-setup` 이 아직 없으니 `package.json` 의 `start` 같은 기존 스크립트를 쓴다. 저장 데이터를 바꾸는 요청은 보내지 않는다.

## 질문은 AskUserQuestion 으로, 단 하나만

6단계 중간 보고에서 객관식으로 묻는 것은 **테스트 도구 선택(질문 OQ) 하나**다. `option.description` 에 설정 파일이 몇 개 필요한지와 기본값을 적는다.
`확인` 종류의 OQ(이 동작이 의도인가, 누가 쓰는가)는 객관식으로 만들지 않는다 — 사용자도 모르는 것을 찍게 되고 그 답이 합의로 문서에 박힌다.
평문으로 목록만 보여 주고 "답을 못 주셔도 지금 동작대로 테스트를 씁니다"를 붙인다.

## 파일 작성

세 문서는 Write 도구로 만든다. `docs/PRD.md` 가 이미 있으면 **쓰지 않는다** — 1단계의 진입 조건이다.
`CLAUDE.md` 가 `/init` 으로 이미 만들어져 있는 경우가 많다. 그때는 Read 로 먼저 읽고, 기존 내용 아래에 뼈대와 세 절을 더한다. 덮어쓰지 않는다.

## 다음 스킬 연결

중간 보고 뒤 사용자가 동의하면 Skill 도구로 `plan-generator` → `harness-setup` → `loop-setup` 을 **순서대로** 부른다.
각 호출에는 SKILL.md 7~9단계의 호출 지시를 프롬프트로 함께 넘긴다 — 스킬 본문은 부른 스킬 것이고, 지시는 이 스킬 것이다.
앞 스킬의 보고를 받은 뒤 다음을 부른다. 셋을 한 번에 띄우지 않는다 — 하네스는 플랜을, 루프는 하네스를 읽는다.

Skill 도구가 없는 환경이면 각 스킬의 `SKILL.md` 를 읽어 그 절차를 그대로 따르고 같은 지시를 자기에게 적용한다.
